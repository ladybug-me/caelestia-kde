# ISS-629 — Installer permanently flips ccache in /etc/makepkg.conf

State: CLOSED (2026-09-06) · Severity: Medium.

## Problem (condensed from the original report)

Months after installing Caelestia the reporter traced unexpectedly long
AUR build times and ccache disk usage to `/etc/makepkg.conf` having
`ccache` enabled in `BUILDENV` — something they never enabled.

Root cause (quoted in the issue): `scripts/01-ensure-prereqs.sh` ran

```bash
sudo sed -i 's/!ccache/ccache/' /etc/makepkg.conf
```

during the one-time "Ensure prerequisites" step. That edits the
system-wide file governing every `makepkg`/AUR build on the machine —
silently, undocumented, and `uninstall.sh` never reverted it, so the
change outlived Caelestia entirely.

## What users see (the symptom this rule fingerprints)

- AUR/makepkg builds behave differently (ccache cache misses eating disk,
  changed build output paths) on a machine where the user never enabled
  ccache.
- `/etc/makepkg.conf` shows `ccache` (no `!`) in `BUILDENV` after a
  Caelestia install.

## Fix direction (as discussed in the issue)

Check and re-disable if unwanted:

```bash
grep BUILDENV /etc/makepkg.conf
sudo sed -i 's/^BUILDENV=(\([^)]*\)ccache /\1!ccache /' /etc/makepkg.conf
```

(distros package the exact syntax differently — inspect the file first).
The upstream fix removed the flip and disclosed the historical change;
users on older versions still carry the modified file.
