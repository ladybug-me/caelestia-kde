# ISS-616 — GPU usage and temperature are averaged across every /sys/class/drm/card* device, producing meaningless numbers on hybrid-graphics/multi-GPU systems

State: CLOSED, stateReason COMPLETED · opened 2026-09-05 by 0x0nYx.

## Problem (original report, condensed)

On my Ryzen APU + discrete AMD GPU desktop, the GPU usage widget shows roughly half of what either GPU is actually doing under load — running a game that pegs the discrete card at 100% while the iGPU sits idle at 0% displays as ~50% in the bar/Nexus resource widgets.

Root cause: `shell/plugin/src/Caelestia/Services/gpu.cpp`, `readGenericUsage()`:
```cpp
const QStringList paths = QDir("/sys/class/drm").entryList({"card*"}, QDir::Dirs | QDir::NoDotAndDotDot);
qreal sum = 0.0; int count = 0;
for (const QString& card : paths) {
    QFile f(QString("/sys/class/drm/%1/device/gpu_busy_percent").arg(card));
    if (f.open(...)) { sum += f.readAll().trimmed().toDouble(&ok); ++count; }
}
const qreal newPerc = count > 0 ? sum / count / 100.0 : 0.0;
```
This walks *every* `cardN` entry that exposes `gpu_busy_percent` and averages them into one number with no attempt to identify which card is the "real"/active GPU (discrete vs integrated, or primary vs secondary in a multi-GPU box). The type-detection script a few lines up (`kTypeDetectScript`) already treats "any card with `gpu_busy_percent`" as sufficient to classify the system as `GENERIC`, so this isn't a one-GPU-assumption edge case — it's the intended code path for any non-Nvidia system, and it breaks the moment there's more than one DRM card.
