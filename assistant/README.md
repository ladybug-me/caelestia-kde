# caelestia-assistant

Offline-first assistant for [caelestia-kde](https://github.com/ladybug-me/caelestia-kde):
deterministic diagnostics, learned routing, natural-language settings editing
(issue #120), stream scanning, and a consent-gated agent — **Python stdlib
only, no LLM in the critical path, no model files ever bundled**.

## What it is

- **core/** — the router (cortex), learners, proposal protocol, and the
  measurement arena. Every user-facing answer is produced by rules,
  retrieval, or learned routing over local data; nothing calls out to a
  network by default.
- **capabilities/** — one plugin per domain (`diagnostics`, `retrieval`,
  `settings`, `brain`, `genius`, `agent`, `shellkb`, `scan`, `graph`,
  `devflow`, `issues`, `generative`), each with a manifest declaring its
  permissions, risk tier, and latency/memory budgets.
- **adapters/caelestia/** — the settings registry and the QML surfaces
  (`AiAssistant`, `SettingsTools`, `CommandGate`) for the shell.
- **executor/** — the single tiny process surface that runs typed
  ActionPlans: argv arrays only, never strings, timeout-bounded, with
  postcondition checks and auto-revert for mutating plans.
- **data/** — corpora and registries (built artifacts are generated at
  release, not committed).

## Install

```sh
pip install .            # stdlib only; nothing else is required
pip install ".[all]"     # optional extras: numpy accelerator, onnxruntime encoder
```

Requires Python 3.12+. The optional extras are accelerators only — every
one has a pure-Python fallback pinned to identical results by tests.

## Usage

```sh
caelestia-assist diagnose FILE        # troubleshooting rules (Layer 1)
caelestia-assist settings "..."       # NL settings (dry-run by default)
caelestia-assist ask "text"           # rules -> retrieval -> optional cloud
caelestia-assist eval [--json]        # the measurement arena
caelestia-assist --help               # every verb, honestly described
```

## Safety model

- Read-only and journaled-reversible actions run without prompts;
  destructive or privileged actions require explicit confirmation.
- Settings changes are dry-run by default; `--apply` writes exactly one
  target file behind a second `--confirm` for multi-change plans, with a
  bounded, single-slot undo history.
- Execution goes through the executor: argv tuples only, `shell=True`
  is structurally unreachable, and every plan carries a reversibility
  class and blast radius.
- Untrusted text (issues, logs, web) is data, never instructions.
- The generative layer is an opt-in, loopback-only fallback tier; it is
  off unless explicitly enabled and never ships a model.
